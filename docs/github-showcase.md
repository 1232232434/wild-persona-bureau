# GitHub Showcase Kit

这份文档不是产品需求文档，而是给比赛展示和 GitHub 呈现准备的“话术 + 顺序 + 截图位”资产包。

## 1. GitHub 首页应该让评委看到什么

建议评委进入仓库后，按这个顺序看到信息：

1. 项目名称和一句话定位
2. 为什么题目不老套
3. 产品链路图
4. SDD 方法图
5. 比赛亮点
6. 本地启动方式
7. `Spec / Plan / Task` 三文档入口

也就是说，`README.md` 不只是说明文档，它本身就是答辩第一页。

## 3. 一分钟答辩版本

如果评委只给你 60 秒，建议这样讲：

1. `野性人格局` 是一个用 SDD 方法做出来的 AI 趣味人格实验项目。
2. 它不做 MBTI 套壳，而是把用户在压力、风险、社交和行动节奏中的选择，转成一份野性人格档案。
3. 前端先把用户答案映射成五维人格分数，再匹配 8 个野性原型。
4. 后端再通过免费模型生成结构化叙事结果，最后输出成海报式结果页。
5. 如果模型输出质量太差，系统会自动回退到本地档案文案，保证演示稳定。

## 4. 三分钟演示版本

### 第一段：先讲项目为什么有记忆点

- 不是“你是什么动物”的普通测试
- 结果页像实验档案，不像普通问卷结果
- GitHub 里还能看到完整的 `Spec / Plan / Task`

### 第二段：再讲产品链路

- 首页建立氛围
- 测试页通过场景题暴露本能
- 系统映射五维人格
- 匹配主原型和次级原型
- AI 生成结果档案
- 导出分享卡

### 第三段：最后讲工程价值

- 前端和 AI 服务层解耦
- 支持 `mock / proxy / fallback`
- 免费模型已经真实联调成功
- 弱模型说空话时，系统会自动回退

## 5. 如果评委问“为什么用 SDD”

建议回答：

`因为这个项目不是单纯做页面，而是要同时把产品概念、技术路线和 AI 工作流讲清楚。Spec 定义我们做什么，Plan 定义我们怎么做，Task 定义执行顺序和人机协作方式，所以这个仓库不仅有结果，也能证明方法。`

## 6. 如果评委问“为什么这个题目不老套”

建议回答：

`因为它不是传统人格标签测试，而是把人格结果包装成一份野外档案。题目是场景化的，结果是可分享的，叙事是 AI 参与生成的，最终出来的是一个能被记住的作品，而不是一个普通小程序壳子。`

## 7. 如果评委问“免费模型会不会太弱”

建议回答：

`我们故意把系统设计成弱模型也能工作。因为前端已经先完成了结构化评分和原型匹配，模型只负责把已有结构转成档案叙事。并且我们加入了低质量检测和 fallback，所以演示时不会因为模型状态不稳定而整体失控。`
